# Show Image To User

## 单一职责

本 skill 定义“把本地图片、GIF 或录屏交付给用户本人看”的项目入口。默认交付动作是：最终 `PASS` 媒体先完成 AI 图面核验和 `PASS` 清单校验，然后用本地网页查看器真实打开或复用既有查看器网址，并在回复里同时给出 `VIEWER_URL`、最终媒体路径和 `PASS` 清单。用户当轮明确说“不要打开 / 只给路径 / 只给网址 / 我自己打开”时，才只输出证据入口、不打开窗口。打开、复用网址或输出路径都只是交付动作，不是验收动作：AI 验收必须先基于图片 / 录屏本身、E2E / 断言和 `PASS` 清单完成，不能用“查看器已打开”“网址已生成”或“脚本成功”证明图面合格。技能名保留历史名称；录屏 / 视频展示不另建第二入口。

- 截图是否具备 E2E / UI 验收资格，不在本入口定义。
- AI 自己读图、核图和 `PASS` / `REVISE`，不在本入口定义。
- 大图安全读取、降采样和裁切，不在本入口定义。
- 本入口不维护第二套截图验收正文；它只裁决选哪张图、如何打开或复用用户可见证据入口、什么时候允许只输出不打开、失败时怎么回报。

AI / 开发者快速检查端到端截图目录时，使用项目工具索引里的本地网页目录查看器（见 [`docs/tools.md`](../../../docs/tools.md)）。这个查看器按证据目录去重、自动刷新并复用图组中文索引；一旦要把图片交付给用户本人看，仍必须回到本入口，先锁定最终 `PASS` 图组或录屏，再用 `open-verified-image.mjs --dry-run` 校验清单，随后用同一份 `PASS` 清单真实调用本地网页查看器。若同一目录 / 同一图组的网址已经存在，复用或返回已打开状态，不使用 `--force-reopen` / `--reopen` 造成重复窗口；只有用户明确说没看到、打开错图、要强制重开或切换通道时，才强制重开。

项目约定：

- 主证据目录：`test-results/evidence-screenshots/<game>/<测试文件>/<用例>/`。
- 候选图、失败图、中间排查图不能冒充最终验收图；它们只能作为路径或诊断材料报告，不允许代理打开给用户看。
- 服务器相册不是默认交付。只有用户明确要求上传、发布链接、服务器相册或手机查看时，才允许发布到 `http://8.148.71.102:18080/#/boardgame/<task-id>`。
- 获得上传授权后，只允许更新 `/home/admin/image-preview/data/projects/boardgame/tasks/<task-id>/`，禁止改预览站壳层、根路由或客户端代码。

## 输出与代开时机（强制）

- 用户当轮说看图、打开图、给截图、截图验收、录屏、玩家视角检查、`图呢`、`我看看` 或类似表达时，默认触发“打开最终 `PASS` 媒体”。证据必须包含 `VIEWER_URL`、最终媒体路径、`PASS` 结论和 `PASS` 清单；只有用户明确说不要打开 / 只给路径 / 只给网址 / 我自己打开时，才不打开窗口。
- 最终 `PASS` 成立后，默认用本地网页查看器打开本轮媒体。查看器已存在时复用同一网址或返回已打开状态，不重复开窗口；这仍然要回报 `VIEWER_URL`，让用户能确认打开的是哪组图。
- 录屏、GIF 和视频属于同一类用户可见验收物：用户要求看实际动效 / 录屏 / GIF 时，最终 `PASS` 后默认打开本地网页查看器。未达到本轮 `PASS` 前，不得把录屏或动图当过程材料打开给用户。
- 输出路径、输出 `VIEWER_URL`、打开或复用查看器都是图片型或动效型交付动作，不是验收动作。实现、测试、截图 / 录屏链、AI 核图或证据选择还没完成时，不得启动本地网页查看器生成最终网址，也不得调用系统查看器、PureRef 或 Codex App 内联展示；最多报告候选路径、缺口和下一步。
- 用户说 `图呢`、`给截图`、`我看看` 或类似表达时，先判断是否已经具备最终验收图、最终有序图组或最终动效录屏：具备则打开或复用查看器并输出 `VIEWER_URL` 和补充证据；不具备则先补实现、补 E2E、补截图 / 录屏链或补核图。禁止为了回应催图而打开旧图、单张候选图、过程图、诊断录屏或截图目录。
- 同一轮同一份媒体或同一组媒体只交付一次。查看器已存在时默认复用，不加 `--force-reopen` / `--reopen`；除非用户明确说没看到、打开错图、要强制重开或要改用另一通道，否则不得重复打开同一组图。
- **最终 PASS 前禁止输出最终图证据或打开（强制）**：本条只在已经触发图片 / 动效交付时生效。本轮截图、录屏、过程图、候选图、诊断图、失败图、过期图和历史图，只要尚未被当前验收流程选为最终交付物并明确判定 `PASS`，一律不得包装成最终可点击网址证据，也不得通过本地网页查看器、系统查看器、PureRef、Codex App 内联图、会在对话中渲染图片的 `view_image` / `Viewed Image` 预览或服务器相册展示给用户。用户明确要求“先打开看看 / 打开失败图 / 打开候选图 / 我看看”也不能绕过；正确动作是继续验收、说明尚未通过，或只给路径与未通过原因。若本轮没有触发图片 / 动效交付，则不需要为了满足本条而主动输出 `PASS` 图或录屏。
- **PASS 只看本轮要求（强制）**：最终 `PASS` 的判断对象是用户本轮明确交给你的要求，不是整页 UI、全游戏完成度或其它顺手发现。输出证据或代理打开前必须先写出“本轮要求清单”，每一项都要有直接证据并标为 `PASS`；任一项未达标、缺证据或被用户刚指出仍不对，都不得作为最终图证据输出或代理打开。非本轮要求的问题可以记录为备注或后续项，但既不能阻塞本轮交付，也不能拿来替代本轮要求的达标证据。若非本轮问题会让本轮截图 / 录屏无法证明目标要求，例如遮住目标、截图不是目标状态、录屏没有覆盖目标动作或流程没有触发，则它按“本轮证据无效”处理。

## 一步到位输出流程

用户要求看图、给截图、打开图或最终截图验收时，只允许按这条正向顺序执行一次：

1. 锁定本轮交付要求清单，并判断需要单图、有序图组还是录屏。
2. 完成当前工作树、当前入口、当前目标状态的截图 / 录屏与必要测试；若需要重跑、补图、同步目录或重建证据，必须在证据交付前完成。
3. 选定最终原图 / 原录屏；单图和多图都必须给本地网页查看器提供用户可读的中文索引，不能让查看器退回英文文件名、测试名或内部路径作标题；代理打开时只能展示本轮 `PASS` 清单覆盖的媒体，不能把同目录里的旧图、候选图、诊断图或英文测试文件一起列给用户；多图时再用项目唯一标记脚本生成 `00-sequence-index.png` 和无遮挡标记副本。
4. 创建或更新只覆盖本轮要求的 `PASS` 清单，确保清单里的测试结果、原图路径、标记图路径和当前证据运行一致。
5. 先用 `open-verified-image.mjs --dry-run` 校验清单和路径；发现旧图、缺图、标注遮挡、清单不匹配或验收项不足时，回到第 2 步修正，不得先输出最终证据或先打开再补救。
6. dry-run 通过后，用同一份 `PASS` 清单和同一组媒体真实调用 `open-verified-image.mjs`。本地网页查看器应打开本轮最终媒体；若同一目录 / 图组已经打开，返回 `ALREADY_OPEN=true` 或同等复用证据即可，不强制重开。
7. 只有用户明确说“不要打开 / 只给路径 / 只给网址 / 我自己打开”时，才用 `open-e2e-image-viewer.mjs --no-open` 注册最终媒体目录并只输出 `VIEWER_URL`、`PASS` 清单和最终媒体路径。`--force-reopen` / `--reopen` 只能用于用户明确说没看到、打开错图、要强制重开或要改用另一通道。

完成第 6 步后，除非用户明确说没看到、打开错图、要重开或切换通道，否则不得再次调用任何会打开窗口或在对话中渲染媒体的通道。同一轮中如果打开或输出后才发现截图、清单或标注不是最终状态，这次交付必须按失败处理；修正后只能在说明前次作废的情况下重建完整链路，不能把多次输出或多次打开包装成正常过程。

## 触发条件

这些表达默认表示用户要看到图片，并触发最终 `PASS` 媒体打开 / 复用查看器：`打开图片`、`打开图`、`图呢`、`给我看图`、`给截图`、`给我截图`、`截图给我`、`截图呢`、`我看看`、`重新打开`。
这些表达才表示只输出证据、不打开窗口：`不要打开`、`不用打开`、`只给路径`、`只给网址`、`给我链接`、`我自己打开`。
这些表达默认表示用户要看到动态媒体，并触发最终 `PASS` 动态媒体打开 / 复用查看器：`录屏`、`动图`、`GIF`、`视频`、`看实际效果`、`看动画效果`。动态媒体仍必须先满足本轮 `PASS` 清单；录制文件存在不等于允许输出最终证据或代理播放。

- 用户明确要看图或给截图时，先判断最终 `PASS` 是否成立；成立才打开或复用查看器，并输出 `VIEWER_URL` 和补充证据，再解释。未成立时不得输出最终证据或打开，只能继续补验收或说明阻塞。
- 工作流已经选定最终验收图、最终有序图组或最终录屏，且 AI 核图通过时，如果本轮属于 UI / 游戏画面 / 截图验收收口，必须以 `task-final-delivery` 打开或复用本地网页查看器并输出 `VIEWER_URL` 和补充证据；不要等用户再追问“图呢”。若只是过程截图、诊断截图、候选截图或非视觉任务附带截图，仍只能报告路径和结论。
- 用户只要求“给路径 / 证据路径”时，只给绝对路径，不输出查看器命令，也不打开查看器。
- `E2E passed`、`截图已生成`、`录屏已生成`、`证据已更新` 不是打开本地查看器的充分依据。用户明确要看图 / 录屏、本轮交付物就是图片型 / 动效型验收物，或本轮已经完成 UI / 游戏画面 / 截图最终验收并选定 `PASS` 验收图时，才进入证据交付流程；进入后仍必须等最终验收物 `PASS` 才允许输出最终证据或打开。
- 已经在上一轮或上一专题收工、打开、输出过或明确降级为独立证据的图组，不得因为新一轮修其它问题而重新打包交付。新一轮只需要引用这些证据时，报告路径和既有结论即可；只有用户重新要求看该专题，或本轮目标本身重新打开该专题验收，才允许创建新的用户展示清单。

## 选图规则

- 选图必须匹配当前目标：PC / mobile / 横屏 / 当前游戏 / 当前流程不能靠宽泛关键词或最新时间戳乱配。
- 修代码、样式、数据后要看当前效果时，默认先重拍当前工作树、当前入口、当前目标状态的新图；旧图只能标为历史证据。
- 单图只能证明单帧。翻页、前后态、PC/移动对照、弹窗开关、流程步骤或分支状态默认交付最小有序图组。
- 原图优先：用户说 `原图`、`未压缩`、`压缩前`、`原始截图` 时，禁止把缩略图、裁切图、OCR 图、contact sheet 或压缩预览当作最终证据输出或代理打开。
- 验收图默认用真实原始截图；标记副本只作为多图顺序辅助，必须保留并汇报原始路径。
- 如果最新相关图是失败、过期或诊断图，只能报告路径和失败原因，不得输出为最终图证据或代理打开；需要继续补实现、补截图或重新验收直到出现最终 `PASS` 图。
- 用户点名只看某个编号之后、某个章节、某个分支或“后续流程”时，必须先按该范围生成新的标注图组和 PASS 清单；不得用更大的历史 PASS 清单顺手输出或打开前置图、辅助图、移动端对照图或诊断图。局部图组第一张必须说明从哪个真实流程点接起；如果接下来进入专题 / 代表态 / 视角分支，用户可见标题必须写明分段起点，不能让连续编号暗示自然承接。

## 代理打开通道

BoardGame 默认交付方式是本地网页查看器打开或复用最终 `PASS` 媒体，并输出可点击访问的 `VIEWER_URL`：

1. 本地网页查看器：图片、GIF、视频、单图和多图的默认打开通道，入口是 `scripts/verify/open-verified-image.mjs`，实际复用 `.tools/e2e-image-viewer/`。
2. Windows / 系统查看器：只有网页查看器无法打开、视频播放异常，或用户明确要求系统查看器时使用。
3. Codex App Markdown 内联：只有用户明确说“在这里打开 / 内联展示 / 发在对话里”，或本地网页查看器和系统查看器都失败时使用。
4. PureRef：不再是默认通道；只在用户当轮明确要求 PureRef，或排查历史 PureRef 清单时显式使用。

执行要求：

- 一次打开只选一个用户展示通道；一个通道成功后，不要再重复打开同一组图。
- 多图用本地网页查看器时必须一次传入同一最终图组目录内的媒体；如果最终证据来自多个截图目录，先生成本轮最终展示目录、中文索引和对应 `PASS` 清单，再真实打开。只做跨目录 `--dry-run` 不能证明用户可见多图能被真实打开。
- 查看器按目录去重，目录已打开时复用既有网址或返回已打开状态，不重复开窗口；只有用户明确要求强制重开时才使用 `--force-reopen` / `--reopen`。
- 多图交付后必须写清顺序映射，例如 `1. PC 选择态：事件牌 + 骰盘 + 属性选项`，不能只说“给了 4 张图”或“打开了 4 张图”。
- `view_image`、OCR、缩略图、裁切图、contact sheet 只有在宿主不会把图片渲染给用户时才可作为 AI 自检；一旦宿主会在对话、任务面板、网页查看器或外部窗口中展示图片，就按用户可见交付处理，必须满足最终 `PASS` 门槛。若没有私有看图通道，未 `PASS` 候选只能用非展示型机器检查、路径和文字证据推进，不能为了 AI 自检先打开。
- 给用户输出截图证据或代理打开，不等于 AI 验收；AI 核图必须另写图面事实和 `PASS` / `REVISE` 结论。

## 多图索引与标记

多张最终验收图默认优先复用或生成图组索引，让本地网页查看器或用户自己打开时能看到中文标题和承接说明；只有需要额外序号图时，才用项目唯一标记脚本生成带序号的全尺寸标记副本：

```powershell
python ".spec/skills/show-image-to-user/scripts/label-image-sequence.py" `
  --out-dir "<evidence-dir>\_labeled-for-pureref" `
  --title "交互流程截图顺序" `
  --image "<absolute-image-path-1>" --label "万箭齐发卡牌：打牌前" --transition "起点：攻击已选中，卡牌仍在手牌" `
  --image "<absolute-image-path-2>" --label "万箭齐发卡牌：卡牌特写" --transition "从 01 打出万箭齐发 -> 弹出卡牌特写，并显示首次奖励骰结果描述"
```

- `.spec/skills/show-image-to-user/scripts/label-image-sequence.py` 是项目内唯一标记脚本；它生成 `00-sequence-index.png`、`NN-labeled-*` 和可供网页查看器读取的图组说明。`_labeled-for-pureref` 是历史目录名，不代表默认使用 PureRef。
- 标记副本必须保持原始截图完整可见；如果序号、标题、说明栏、遮罩或水印压住了游戏画面、牌面、教程卡、按钮、地图、骰子或其它验收对象，该标记副本只能作诊断废图，不能进入 PASS 清单、不能输出为最终图证据，也不能替代原图验收。
- 本地网页查看器在代理打开时默认打开图组目录；地址栏使用短 `key`，页面左侧索引显示中文说明，并按目录去重。即使本轮只打开一张图，也要在截图目录写入 `.e2e-image-index.json` 或等价索引，让用户看到中文标题和本轮验收对象，而不是英文文件名。若截图目录还包含其它媒体，代理打开入口必须过滤到本轮 `PASS` 清单媒体，避免用户可见列表混入未验收内容。
- 标记图和索引里所有用户可见标题、步骤标签、承接说明和补充说明必须使用中文；原始文件名、代码文件名、测试名、`PASS` / `VIEWER_URL` 等技术输出可以保留作机器证据或终端日志，但不能替代用户可见中文说明。
- 标签必须写玩家能懂的步骤和对象类型，例如 `卡牌`、`技能`、`响应窗口`、`骰盘`，不能只写文件名、测试名或内部字段。
- 每张图从第二张开始必须说明相对上一张发生了什么；第一张必须说明起点或前置状态。
- 用户明确要求不加标记时，打开或复用原图目录并输出 `VIEWER_URL`、原图目录和有序映射；如果多图原图分散在多个目录，先复制到本轮最终展示目录并写入中文索引。必要时可另开独立序列索引。

## 执行入口

默认执行入口分三类：先校验 `PASS` 清单和路径，再真实打开或复用本地网页查看器，最后输出 `VIEWER_URL`、媒体路径和清单。`--no-open` 只在用户明确要求只给网址 / 路径、不打开窗口时使用。

校验单图 / 录屏 / 视频：

```powershell
node scripts/verify/open-verified-image.mjs --dry-run --pass-manifest "<本轮要求达标清单.json>" --path "<单张最终原图或录屏绝对路径>"
```

校验多图：

```powershell
node scripts/verify/open-verified-image.mjs --dry-run --pass-manifest "<本轮要求达标清单.json>" --paths "<00-sequence-index.png>" "<01-labeled-*.png>" "<02-labeled-*.png>"
```

只生成可点击网址（仅当用户明确不要打开）：

```powershell
node scripts/verify/open-e2e-image-viewer.mjs --dir "<最终媒体所在目录>" --focus "<首张媒体文件名>" --files "<媒体文件名1>" "<媒体文件名2>" --no-open
```

打开或复用单图 / 录屏 / 视频：

```powershell
node scripts/verify/open-verified-image.mjs --pass-manifest "<本轮要求达标清单.json>" --path "<单张最终原图或录屏绝对路径>"
```

打开或复用多图：

```powershell
node scripts/verify/open-verified-image.mjs --pass-manifest "<本轮要求达标清单.json>" --paths "<00-sequence-index.png>" "<01-labeled-*.png>" "<02-labeled-*.png>"
```

- `scripts/verify/open-verified-image.mjs` 是 `PASS` 清单和路径的校验入口，也是默认打开 / 复用入口。默认交付必须先执行 `--dry-run` 校验，再用同一参数去掉 `--dry-run` 真实打开或复用查看器。
- `scripts/verify/open-e2e-image-viewer.mjs --no-open` 是“只给网址、不打开”入口；只有用户明确不要打开时使用。输出中的 `VIEWER_URL=...` 是补充证据，不是图面验收。
- `--pass-manifest` 指向的 JSON 必须只覆盖本轮用户要求，最低结构为：`verdict: "PASS"`、`scope: "current-user-request"`、`display: { "purpose": "final-user-visible-delivery", "trigger": "user-requested-evidence" | "user-requested-proxy-open" | "task-final-delivery", "viewer": "web", "finalPassBeforeOpen": true }`、`requirements: [{ requirement, status: "PASS", evidence: [...] }]`、`images: [...]` 或 `media: [...]`。脚本会校验每项要求都是 `PASS`、证据非空、交付目的为最终用户可见交付，并且本次涉及的图片 / GIF / 视频全部在清单中；这防止用“过程核图 / 我确认过了 / 泛化 UI PASS”代替本轮最终达标。
- `user-requested-open` 只作为历史 PASS 清单兼容值保留；新清单必须按现实动作区分 `user-requested-evidence` 和 `user-requested-proxy-open`。
- 查看器入口会记录最近成功打开的 PASS 清单和媒体列表；同一份清单或同一组媒体默认复用或返回已打开状态，不应报成失败。只有用户明确说没看到、打开错图、要强制重开或要改用另一通道时，才允许在同一命令后追加 `--force-reopen` / `--reopen`。
- PASS 清单必须覆盖截图可理解性所依赖的关键画面对象：如果最终图组里可见的卡牌、法术、技能、装备、附件、单位或牌库 / 法术书是本轮流程、动画来源、目标或上下文承载，必须有证据说明这些牌面 / 素材已经真实渲染、不是空白壳层或纯色占位。关键牌面空白时，不管动画像素、E2E、文件路径或脚本校验是否成功，都不得创建 `PASS` 清单，也不得输出为最终图证据或代理打开给用户。
- PASS 清单只写本轮验收对象；相邻按钮、牌堆、阶段条、HUD 或其它同屏元素只能作为“不遮挡 / 不相交 / 不抢职责”的辅助证据，不能混成第二个独立需求。若用户要求看“回合流程”，清单主项必须是阶段信息条；“确认计划 / 结束行动 / 结束回合”这类主操作按钮只能按按钮自己的任务另开验收项。
- 多图、`--paths`、`--path` 重复参数一律直接调用上述 `node` 入口；不要通过 `npm run verify:open-image -- --paths ...` 转发参数，避免 npm 把 `--paths` 或图片路径解析成自己的参数并产生误导性 warning。
- `open-e2e-image-viewer.mjs --no-open` 成功只证明可点击网址已经生成；打开脚本成功只证明打开 / 复用动作已发起并有进程 / 命令结果。用户说没看到、打开错图、图被标注遮挡、只有一张或图为空时，按展示失败处理。若问题来自最终图或标记副本本身不真实，必须撤销本轮 PASS 清单并重新生成无遮挡图组；不得用同一清单反复重开。
- Codex App 内联只能使用绝对本地路径：`![说明](D:/absolute/path/image.png)`；路径含空格时用 `![说明](<D:/path with spaces/image.png>)`。

## 收口门禁

发送最终回复前做五问：

0. 本轮是否明确触发图片 / 动效交付：用户要求打开 / 看图 / 给截图 / 截图验收 / 录屏 / GIF / 看实际动效，任务交付物本身就是图片型 / 动效型验收物，或本轮已经完成 UI / 游戏画面 / 截图最终验收并选定 `PASS` 验收图？
1. 本轮是否已经选定最终用户验收图、最终有序图组或最终动效录屏？
2. AI 是否已经对同一张原图、同一组原图或同一份录屏给出通过结论，并用 `open-verified-image.mjs --dry-run` 校验过清单和路径？
3. 同一轮是否已经打开或复用本地网页查看器，并输出可点击访问的 `VIEWER_URL`、最终媒体路径和 `PASS` 清单？如果用户明确不要打开，是否已说明只输出的依据？
4. 若查看器已有网址，是否复用 / 返回已打开状态而不是重复开窗口？如果打开失败，是否给出失败证据和最小补救动作？

如果 0 为否，不主动调用查看器；只按任务需要汇报截图清单、路径、核图结论或 evidence。若 0、1、2 为是而 3 为否，禁止收口；先打开或复用查看器并输出 `VIEWER_URL` 再汇报。子 agent 可以协助找图、核图、生成标签、执行 dry-run 或生成 `VIEWER_URL`；父 agent 负责当前用户可见回复，不能把子 agent 私有消息、`view_image` 预览、路径或查看器命令当成用户已看到。

## 失败处理

- 路径找不到：先列目录核实，再用解析后的绝对路径重试。
- 文件来自截图工具：先确认存在且大小非零。
- `--dry-run` 未通过：不得输出最终 `VIEWER_URL` 或代理打开；汇报哪个现实交付条件未满足、证据在哪里、为什么阻止交付、最小补救动作是什么。
- 无法打开 / 复用本地网页查看器或生成 `VIEWER_URL`：汇报本地网页查看器打开失败的现实后果、`logs/e2e-image-viewer.log` 或命令输出里的证据、为什么阻止用户看图、最小补救动作；必要时再按同一 `PASS` 清单降级系统查看器，并说明这不是默认通道。
- 输出入口不足：如果没有 `VIEWER_URL`，只输出已校验的最终媒体绝对路径、`PASS` 清单路径和可复制命令作为兜底，并明确“图未按默认通道打开”。
- 本地网页查看器启动失败：先查看 `logs/e2e-image-viewer.log`，确认端口和目录；仍无法展示时才转系统图片查看器。
- 目录复用失败或意外打开了新网页窗口：汇报目录 key、端口和状态文件，不说“已复用旧窗口”。
- 内联图未渲染：只有用户明确要求在对话里展示时才改走本地网页查看器 / 系统图片查看器；否则输出 `VIEWER_URL`、路径和命令即可。
- 本地网页查看器、系统图片查看器和内联都失败：汇报目标路径、文件是否存在、尝试过的通道、最小补救动作；不要反复重开。
